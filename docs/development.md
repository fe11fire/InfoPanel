## Структура репозитория

```text
index.html                 # разметка, порядок подключения скриптов и запуск
assets/
├── css/                   # оформление и шрифтовые стили
├── themes/                # пять тем, общие детали и шаблон своей темы
├── fonts/                 # локальные шрифты
├── js/
│   ├── config/            # адрес клиента, значения по умолчанию, проверка настроек
│   ├── content/           # очередь основного контента и модули
│   ├── lines/             # очередь нижних строк и модули
│   ├── request.js         # HTTP-запросы и проверка ответов
│   ├── errors.js          # сообщения, TTL и индикатор
│   ├── library.js         # общие функции
│   ├── clock.js           # часы и календарь
│   └── matrix.js          # визуальный эффект перехода
└── pdfjs/                 # готовая сборка PDF.js и уведомления о лицензиях
backend/
├── backend.exe            # готовый сервер для Windows
├── config.json.example    # пример рабочих настроек
└── src/                   # Go-модуль, реализация API и тесты
content.example/           # пример структуры и содержимого
tests/                     # Node.js-тесты и браузерная проверка Swiper
docs/                      # документация
```

Рабочие `content`, `backend/config.json` и установленные `node_modules` исключены из Git. Не подменяйте примеры рабочими персональными данными.

## Зависимости

Для обычной установки пользователю достаточно распаковать `node_modules.rar` рядом с `index.html`. Это автономный вариант поставки для компьютеров без интернета и установки пакетов; [пользовательская инструкция](usage.md) не требует командной строки. Команды ниже относятся только к разработке.

```powershell
npm ci
```

Команда выполняется в корне проекта по `package-lock.json`. Версии прямых зависимостей закреплены в `package.json`: Bootstrap 5.3.0, jQuery 3.7.1, Moment 2.29.4, Plyr 3.7.8, Swiper 10.2.0.

На готовом экране Node.js и Go не нужны: используются файлы библиотек из архива, готовый PDF-движок и серверный бинарник. Для разработки lock-файл фиксирует официальные пакеты npm; он не воспроизводит возможные локальные изменения в архиве.

## Сборка Go-backend

Нужен Go 1.25 или новее: используется `os.OpenRoot`. На Windows из корня проекта:

```powershell
cd backend/src
go test ./...
go build -trimpath -ldflags="-s -w" -o ../backend.exe .
```

Перед заменой бинарника остановите работающий `backend.exe`. После сборки запустите его снова. Настройки и относительные пути разрешаются от каталога исполняемого файла.

Сборка Windows x64 на macOS или Linux:

```sh
cd backend/src
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o ../backend.exe .
```

Для нативного запуска на macOS/Linux:

```sh
cd backend/src
go test ./...
go build -o ../backend .
../backend
```

Предварительно создайте `backend/config.json` и рабочий `content`. Клиент открывайте из `index.html`: сервер обслуживает API, а не статический сайт. Отдельного Node-сервера в проекте нет.

## PDF-движок

В `assets/pdfjs/pdf-engine.js` поставляется готовый движок на базе **PDF.js 6.5.438** со встроенными ресурсами и кодом worker. Установка пакетов и сборка не требуются. Сохраняйте уведомления о лицензиях в `assets/pdfjs/THIRD-PARTY-NOTICES.txt`.

## Проверки

| Проверка | Команда / запуск | Что проверяет |
| --- | --- | --- |
| Клиентские автоматические тесты | `node --test tests/*.test.js` из корня | Очередь, таймеры, ошибки запросов, валидацию, пути, дни рождения, последовательность PDF и загрузку тем |
| Go-тесты | `go test ./...` из `backend/src` | Маршруты API, чтение файлов, ограничения доступа и выдачу PDF |
| Браузерная проверка | Открыть `tests/presentation-browser.html` | Реальный Swiper: эффекты, повторный показ и скрытый при запуске контейнер |
| Ручная проверка | `backend/backend.exe` и `index.html` | Фактические медиа, PDF.js/worker, autoplay, доступ к общей папке и длительную работу |

Node-тесты используют `node:test`, `assert` и `vm`, подменяя DOM, таймеры, запросы и медиакомпоненты. Они не запускают настоящий браузер и не подтверждают поддержку кодеков, сетевого файлового доступа или политики CORS. Браузерная страница Swiper также подменяет API и проверяет конкретно работу презентации. Параметр `?legacy` включает прежнее ожидание перехода для сравнения.

Для ручной проверки добавьте и удалите файлы во время работы, измените настройки, отключите один источник, затем восстановите доступ к нему. Убедитесь, что контент возвращается, а следующий элемент воспроизводится после ошибки. Для общей папки повторите проверку на другом компьютере.

## Добавление модуля основного контента

1. Создайте класс в `assets/js/content/modules` по [протоколу модуля](architecture.md#протокол-модуля-основного-контента).
2. Подключите файл в `index.html` до `contentRouter.js` и добавьте класс в `ContentRouter.#sources`.
3. Добавьте `with_<name>` в `Default.system`, правило в `ConfigRules` и параметр в пример JSON. Новые параметры должны иметь стандартное значение и проверку.
4. Реализуйте `getData()` и `makeJob()`, при необходимости добавьте серверный маршрут. Идентификатор задания должен устойчиво различать элементы разных модулей.
5. В `show()` возвращайте Promise до окончания показа и очистки. Не вызывайте следующий элемент самостоятельно. Освобождайте таймеры, обработчики и медиакомпоненты также при ошибке.
6. Добавьте проверку значимого сценария: завершение, сбой или очистка. Затем проверьте настоящий показ в браузере и обновите документацию.

Для нижней строки подключение выполняется через `LineRouter.#sources`, а договоренность включает `makeLine()`, `show()` и `hide()`.

## Подготовка к передаче на экран

Соберите backend после изменения Go-кода. Запустите проверки, подготовьте браузерные библиотеки в `node_modules.rar` или уже распакованной папке `node_modules` и сохраните соседство файлов проекта. Проверьте запуск из готовой папки на ПК без доступа в интернет. Пользователь не должен устанавливать пакеты или запускать сборку. Персональный контент и рабочий JSON передавайте отдельно от изменений исходников. Замену файлов выполняйте при остановленном сервере, затем перезагрузите страницы клиентов и проверьте используемые форматы.

## Параметры браузера для выделенного экрана

Для полноэкранного запуска Chrome в свойствах ярлыка можно указать:

```text
"C:\Program Files\Google\Chrome\Application\chrome.exe" --start-fullscreen "file:///C:/InfoPanel/index.html"
```

Если браузер блокирует нужный автоматический запуск видео, на выделенном экране можно отдельно проверить флаг `--autoplay-policy=no-user-gesture-required`. Поведение зависит от установленной версии и политик браузера. Эти параметры необязательны для первого запуска; пользовательская инструкция использует обычное открытие HTML и F11.

## Добавление оформления

Темы не требуют npm, изменения Go-кода или регистрации в роутере. Скопируйте `assets/themes/template` под новым именем, измените CSS и укажите имя папки в `theme`. Правила переменных, приоритет JSON и точки оформления описаны в [руководстве по кастомизации](customization.md). При изменении базовых CSS-параметров синхронизируйте значения `Default.css` и `common.css`.
