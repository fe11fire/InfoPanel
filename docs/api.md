# HTTP API

[← README](../README.md) · [Архитектура](architecture.md) · [Настройки](configuration.md)

## Общие правила

Базовый адрес по умолчанию — `http://127.0.0.1:8084`. Браузер берет его из `assets/js/config/client.js`, сервер — адрес прослушивания из `backend/config.json`. Backend обслуживает API, но не `index.html` и не обычные статические файлы проекта.

Маршруты данных принимают GET и POST; клиент использует POST с параметрами `application/x-www-form-urlencoded`. Параметры также можно передать в query string. OPTIONS возвращает 204 для CORS. Прочие методы получают 405. Размер тела запроса ограничен 1 МиБ.

JSON-ответы имеют `Content-Type: application/json; charset=utf-8`. `/config` возвращает объект непосредственно; остальные маршруты данных — объект с массивом `result`. Сервер выставляет `Cache-Control: no-store` и `Access-Control-Allow-Origin: *`. Авторизации нет.

## Маршруты

| Маршрут | Параметры | Ответ / источник |
| --- | --- | --- |
| `/config` | — | Содержимое `config.json`, без обертки `result` |
| `/video` | — | Имена файлов `path_video` |
| `/imgs`, `/img` | — | Имена файлов `path_images` |
| `/text` | — | Имена файлов `path_text` |
| `/text` | `name` | Непустые строки указанного файла |
| `/present` | — | Имена папок `path_present` |
| `/present` | `path` | Файлы внутри презентации, кроме `title.txt` |
| `/present` | `path`, `title=true` | Непустые строки `title.txt` |
| `/birthdays` | — | Объекты `{ date, fio }` из `path_birthday/file_birthday` |
| `/birthday` | `day`, `month` | Имена с совпадающим днем и месяцем |
| `/holiday` | `day`, `month` | Названия из `path_holiday/file_holiday` для дня и месяца |
| `/pdf` | — | Имена обычных файлов `.pdf` из `path_pdf` |
| `/pdf` | `name`, только GET | Бинарное содержимое документа |

Списки не рекурсивные. Серверные списки изображений и видео не являются проверкой формата: фильтр исключаемых расширений применяется на клиенте. `/pdf` отдельно отбирает расширение `.pdf` без учета регистра.

Примеры ответов:

```json
{"result":["video1.mp4","video2.mp4"]}
```

```json
{"result":["Первая строка объявления","Вторая строка"]}
```

```json
{"result":[{"date":"12.10","fio":"Иван Иванов"},{"date":"21.11.1990","fio":"Анна Петрова"}]}
```

`/birthday` оставлен как отдельный маршрут API. Текущие клиентские модули поздравлений используют полный `/birthdays` и сами рассчитывают ближайшую дату, перенос 29 февраля и юбилей. `/holiday` сравнивает день и месяц непосредственно; модуль праздников не подключен к текущему `LineRouter`.

## Получение PDF

```http
GET /pdf?name=SinglePage.pdf
```

Ответ — `application/pdf` с `X-Content-Type-Options: nosniff`. Используется `http.ServeContent`, поддерживающий частичные запросы. Текущий клиент скачивает документ целиком и не использует постраничную сетевую загрузку.

Имя должно обозначать один PDF внутри настроенного каталога. Разделители пути, выход в родительский каталог и неподходящее расширение отклоняются. Проверяются обычный тип файла и размер не более 100 МиБ. Для доступа используется `os.OpenRoot`; символические ссылки не служат способом произвольного чтения за пределами корня.

## Ошибки и особенности

| Код / ответ | Условие |
| --- | --- |
| 400 | Невозможно разобрать параметры запроса или недопустимое имя PDF |
| 404 | Неизвестный маршрут, отсутствующий или недоступный PDF |
| 405 | Неподдерживаемый метод; скачивание PDF требует GET |
| 413 | PDF превышает 100 МиБ |
| 500 | Невозможно прочитать или разобрать `backend/config.json` |
| 200 и пустой `result` | Нет записей; для ряда операций также отсутствует или не читается каталог/текстовый файл |

Ошибки HTTP передаются текстом, не в JSON-обертке. Для списков и текстовых данных пустой ответ не всегда позволяет отличить отсутствие файлов от ошибки чтения: проверяйте серверный журнал. Отсутствующий `title.txt` дает пустой список строк и считается допустимым.

Конфигурация читается до обработки маршрута, поэтому поврежденный JSON влияет на все API. При запуске с отсутствующим или некорректным JSON сервер завершает работу. Настройки оформления и интервалов валидируются клиентом, а не Go-backend.

## Проверка из PowerShell

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8084/config
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8084/present -Body @{ path = 'Safety'; title = 'true' }
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8084/pdf
Invoke-WebRequest -Uri 'http://127.0.0.1:8084/pdf?name=SinglePage.pdf' -OutFile SinglePage-copy.pdf
```

При обращении из собственного клиента кодируйте имена файлов как параметры URL, например через `URLSearchParams`. Реализация контракта: [main.go](../backend/src/main.go) и [pdf.go](../backend/src/pdf.go).
