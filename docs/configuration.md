# Настройки

[← README](../README.md) · [Установка и использование](usage.md) · [Архитектура](architecture.md)

## Где находятся настройки

| Файл | Роль | Применение изменений |
| --- | --- | --- |
| `backend/config.json` | Адрес прослушивания, пути, параметры показа и оформления | Параметры показа — при опросе; IP/порт — после перезапуска сервера |
| `assets/js/config/client.js` | Адрес API, к которому обращается браузер | После перезагрузки страницы |
| `assets/js/config/default.js` | Стандартные значения клиента | Это исходный код; обычные настройки меняйте в JSON |
| `assets/js/config/rules.js` | Правила проверки параметров | Это исходный код |

Начальная конфигурация: [config.json.example](../backend/config.json.example). Создайте ее рабочую копию без `.example`. JSON не допускает комментариев и запятых после последнего свойства.

**Таблицы ниже показывают стандартные значения из кода.** Пример конфигурации намеренно отличается: например, в нем `side_changing: true`, громкость 0, интервал обновления 10000 мс и высота строки 80px. Явно записанное корректное значение из рабочего JSON имеет приоритет.

Все временные интервалы указываются в миллисекундах. Ненулевые интервалы должны быть положительными числами; `config_update_interval` — не меньше 10000. Логические параметры принимают JSON-значения `true` и `false`, без кавычек.

## Адрес сервера и пути

| Параметр | Значение / пример | Назначение |
| --- | --- | --- |
| `server_ip` | `127.0.0.1` | Интерфейс прослушивания backend; для сети задайте IP основного компьютера |
| `server_port` | `8084` | Порт backend, от 1 до 65535 |
| `path_video` | `..\\content\\video` | Каталог видео |
| `path_images` | `..\\content\\imgs` | Каталог изображений |
| `path_present` | `..\\content\\present` | Каталог папок презентаций |
| `path_pdf` | `..\\content\\pdf` | Каталог PDF; также стандартный путь Go-backend |
| `path_text` | `..\\content\\text` | Каталог текстовых объявлений |
| `path_birthday` | `..\\content\\birthday` | Каталог файла дней рождения |
| `file_birthday` | `birthday.txt` | Имя файла дней рождения |
| `path_holiday` | `..\\content\\holiday` | Каталог файла праздников для API |
| `file_holiday` | `holiday.txt` | Имя файла праздников |

Пути в JSON считаются относительно каталога исполняемого backend. Для `path_video`, `path_images`, `path_present`, `path_text`, `path_birthday`, `path_holiday` заполняйте значения из примера: у Go-backend для них нет автоматической подстановки каталогов. Отсутствующий путь дает пустой список. Клиентские стандартные пути к медиа не заменяют серверную конфигурацию.

Клиент преобразует `path_video`, `path_images`, `path_present` в адреса относительно страницы: `..\\content\\video` превращается в `content/video/`. Поддерживаются прямые и обратные разделители, пробелы и кириллица кодируются для URL. Абсолютные пути и выход за каталог проекта отклоняются клиентской проверкой этих параметров. `path_pdf` проходит ту же проверку, хотя сам PDF передается через API. Для предсказуемого запуска держите контент внутри проекта.

`file_birthday` и `file_holiday` должны быть простыми именами файлов без разделителей пути. `path_holiday` и `file_holiday` обслуживаются API, но сами по себе не включают отображение праздников: `Holiday` не подключен к текущему роутеру.

Клиентский адрес задается отдельно:

```js
globalThis.InfoPanelClient = {
    server_ip: '127.0.0.1',
    server_port: 8084,
};
```

При отсутствии клиентских настроек также используется `127.0.0.1:8084`. Получить адрес сервера из `/config` до установления соединения невозможно, поэтому эти два места настраиваются согласованно. Пример сетевого запуска — в [руководстве](usage.md#несколько-экранов-через-общую-папку-windows).

## Включение модулей

| Параметр | По умолчанию | Блок |
| --- | --- | --- |
| `with_present` | `true` | Презентации из изображений |
| `with_imgs` | `true` | Отдельные изображения |
| `with_pdf` | `true` | PDF-документы |
| `with_text` | `true` | Текстовые объявления |
| `with_birthdays` | `true` | Основной список дней рождения |
| `with_video` | `true` | Видео |
| `with_birthday` | `true` | Поздравление сегодня в нижней строке |
| `with_next_birthdays` | `true` | Ближайшие дни рождения в нижней строке |

Выключенный источник не опрашивается при следующем обновлении его очереди. Текущий показ завершается, новые задания этого источника не запускаются. При пустой основной очереди отображаются часы, даже если нижние строки включены.

Пример параметров для режима с изображениями:

```json
{
  "with_present": false,
  "with_imgs": true,
  "with_pdf": false,
  "with_text": false,
  "with_birthdays": false,
  "with_video": false,
  "with_birthday": false,
  "with_next_birthdays": false
}
```

Добавьте эти свойства в существующий рабочий объект JSON, сохранив пути и параметры сервера.

## Время показа и поведение

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `request_timeout` | `5000` | Ожидание ответа обычного API-запроса |
| `config_update_interval` | `20000` | Период опроса конфигурации; минимум 10000 |
| `jobs_restart_timeOut` | `10000` | Пауза перед повтором пустой очереди или после ошибки ее обновления |
| `start_timeOut` | `3000` | Стартовая задержка и интервал повторной проверки возврата с заставки |
| `content_img_interval` | `10000` | Показ одного изображения |
| `content_text_interval` | `10000` | Показ одного объявления |
| `content_present_interval` | `10000` | Показ одного слайда презентации |
| `content_pdf_interval` | `10000` | Показ одной страницы PDF |
| `content_birthdays_interval` | `10000` | Показ основного списка дней рождения |
| `info_line_changing_interval` | `15000` | Интервал ротации нижних строк, без времени запросов |
| `video_stall_timeout` | `15000` | Допустимое время без продвижения видео |
| `content_video_volume` | `0.5` | Громкость, число от 0 до 1 |
| `content_present_sort` | `"default"` | Порядок слайдов: `default`, `asc`, `desc` |
| `side_changing` | `false` | Периодически менять расположение колонок |
| `side_changing_interval` | `15000` | Интервал смены сторон |
| `matrix_enable` | `false` | Эффект «Матрица» при старте/смене сторон |
| `matrix_duration` | `2000` | Длительность эффекта перехода |
| `header_text` | `""` | Заголовок панели, допускает разрешенную разметку |

Общего ограничения длительности видео нет: ролик с прогрессом играет до конца. Ограничение старта видео — 5 секунд. Для PDF скачивание, открытие, получение и отрисовка страницы ограничены 30 секундами на операцию; `request_timeout` не управляет этими PDF-операциями. Показ целого PDF или презентации не ограничен интервалом одного слайда: показываются все страницы/слайды.

## Дни рождения

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `birthday_leap_day` | `"less"` | 29 февраля в невисокосном году: `less` — 28 февраля, `more` — 1 марта |
| `content_birthdays_next_count` | `5` | Число будущих записей в основном списке, включая сегодня |
| `content_birthdays_prev_count` | `2` | Число прошедших записей в основном списке |
| `line_next_birthdays_count` | `5` | Число ближайших записей в нижней строке, без сегодня |
| `content_birthdays_max_font_size` | `24` | Максимальный размер шрифта основного списка, пиксели |

Количество — целое число от 0, размер шрифта — положительное число. Прошедшие даты сортируются по фактическому предыдущему дню рождения, юбилей считается на год этой даты. Формат исходного файла описан в [руководстве](usage.md#дни-рождения).

## Исключение расширений

`content_extensions_ignore` — объект массивов расширений без точки. Обязателен массив `common`; остальные ключи соответствуют статическому имени модуля. Сравнение не учитывает регистр.

Стандартное значение:

```json
{
  "common": ["db", "ini", "ds_store", "tmp", "temp", "bak", "swp", "lnk", "url", "part", "crdownload"],
  "imgs": ["txt"],
  "present": ["txt"],
  "video": [],
  "text": []
}
```

Фильтр применяется к спискам файлов и названиям презентаций, но не к строкам текстов и заголовков. Это список исключений, а не список поддерживаемых форматов. Значение объекта заменяется целиком: задавая собственные исключения, сохраняйте необходимые общие расширения. PDF дополнительно фильтруется сервером по `.pdf`.

## Оформление

Значения ниже — строки CSS. Браузер проверяет их через `CSS.supports`. Для размеров указывайте единицу измерения, например `"80px"`, для цветов — CSS-цвет. `background_color` и `info_line_background_color` также допускают поддерживаемые значения фона, включая градиенты.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `cursor` | `"default"` | Вид курсора; `"none"` скрывает его |
| `background_color` | `"#08184f"` | Фон панели |
| `padding_top` | `"20px"` | Верхний отступ |
| `padding_bottom` | `"20px"` | Нижний отступ |
| `padding_left` | `"50px"` | Левый отступ |
| `padding_right` | `"50px"` | Правый отступ |
| `header_height` | `"80px"` | Высота шапки |
| `header_font_size` | `"26px"` | Размер текста шапки |
| `header_color` | `"#fff"` | Цвет текста шапки |
| `info_line_height` | `"40px"` | Высота нижней строки, когда есть строки для показа |
| `info_line_background_color` | `"linear-gradient(#08184f, #9198e5)"` | Фон нижней строки |
| `logo_width` | `"100px"` | Ширина логотипа |
| `calendar_color` | `"#fff"` | Цвет календаря |
| `calendar_day_font_size` | `"75px"` | Размер числа календарного дня |
| `calendar_text_font_size` | `"20px"` | Размер месяца и дня недели |
| `clock_color` | `"#fff"` | Цвет цифровых часов |
| `clock_size` | `"50px"` | Размер текста цифровых часов |
| `birthday_name_font_size` | `"30px"` | Размер имени в поздравлении |
| `birthday_text_font_size` | `"24px"` | Размер текста поздравления |
| `birthday_color` | `"#fff"` | Цвет поздравления |

Логотип загружается по фиксированному пути `content/logo.png`; отдельной настройки его адреса нет. Текст и основной список дней рождения дополнительно подгоняют размер шрифта по доступной области.

## Ошибки и правила применения

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `show_errors` | `true` | Показывать желтый индикатор поверх панели и заставки |
| `error_ttl` | `300000` | Срок хранения ошибки после последнего повтора, мс |

Порядок обработки параметров:

1. Клиент получает объект `/config`.
2. `ConfigRules` проверяет известные параметры показа, CSS, переключатели и клиентские пути.
3. Отсутствующее или `null`-значение использует стандартное без сообщения об ошибке.
4. Неправильный параметр исключается из полученного объекта в памяти; вместо него используется `Default`, остальные корректные параметры сохраняются.
5. В консоли регистрируется причина. Рабочий JSON автоматически не изменяется.

Для серверных путей, имен файлов и адреса прослушивания действуют правила backend; клиентский валидатор не является полной проверкой серверного JSON. Все параметры и их роли следует сверять с примером конфигурации.

Пока некорректное значение остается в файле, повторный опрос продлевает TTL ошибки. Успешный запрос не удаляет ее немедленно. После исправления значок исчезает по истечении срока последнего повтора. Изменение `error_ttl` применяется к уже существующим ошибкам, `show_errors: false` скрывает значок, сохраняя сообщения в консоли.

При поврежденном JSON или недоступности `/config` конфигурация считается отсутствующей и показываются часы. Последние `show_errors` и `error_ttl` сохраняются, остальная успешная конфигурация целиком не удерживается. После восстановления следующие опросы возвращают панель к работе.
